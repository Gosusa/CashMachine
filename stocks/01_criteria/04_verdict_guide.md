# Verdict 가이드 — "15%+ 장기 복리 가능한가" 판정

이 가이드를 따르면 `02_tickers/{TICKER}/{TICKER}_verdict.md` 파일이 생성된다.

> verdict는 [02_base_guide.md](02_base_guide.md)로 작성된 base.md의 측정 결과를
> [01_philosophy.md](01_philosophy.md) 렌즈로 정제한 **판정·근거·결론 전용 파일**이다.
> 서버에 업로드되는 최종 산출물이므로 **한 번 읽고 판정이 서야 한다**.
>
> base(원재료 측정) → verdict(판정) → 가격 판정(상위 portfolio 단계)

---

## 핵심 원칙

1. **판정 중심**. verdict만 읽어도 "15%+ 가능한가"의 답과 근거가 끝나야 한다.
   base.md를 열어야만 이해되면 작성 실패.
2. **지지·반대 대등**. philosophy "지지 증거와 반대 증거를 대등하게" 원칙을 구조로 강제.
   한쪽만 있으면 확증(YES 편향) 또는 기각(NO 편향)일 뿐 판단이 아니다.
3. **가격 판정 금지**. "이 종목이 15%+ 가능한가"만 판정한다. 매수/매도는 상위 portfolio 단계.
   가격 범위는 **표기**만 수행한다.
4. **증거는 base 링크로**. verdict에 수치를 복제 저장하지 않는다. 출처 단일화.

---

## 분량 가이드

- 전체 **150~270줄** 목표 (§0 "회사 한눈에" 20~30줄 포함).
- base(600+)의 "두 번째 버전"이 되면 실패. 판정 밀도 ≫ 측정 반복.
- 측정 상세는 base 소관. verdict는 base 측정을 판정으로 **축약·대조**한다.
- 체크리스트 적용 결과·요약 블록은 본문에 넣지 않는다 (판정 밀도 희석). 체크리스트는 작성자 자가점검용.

## 파일 구조

```
# {TICKER} — {회사명} · Verdict
> 메타 (작성일 / 카테고리 / 전환 방향)
---
## 이 회사는 무엇을 하는가   ← §0. 첫독자 컨텍스트 (20~30줄)
## 판정 (TL;DR)              ← 10줄 안에 판정·근거 끝
## 1. 스토리 — "15%+ 가려면 무엇이 일어나야 하는가"
## 2. 15%+ 판정 근거 — 지지/반대 대등 + 우열
## 3. 10배 요소 판정
## 4. 카테고리 결론
## 5. 회피 게이트 (부채 · 경영진)
## 6. 가격 범위 · 15% 경로 기준선
## 7. 감지 대시보드
```

**모든 카테고리 동일 처리**: Stalwart·Fast Grower뿐 아니라 Cyclical·Slow Grower·Turnaround·Asset Play도
§1~7 동일 구조로 작성한다. 카테고리별 "추가 강조점"을 §1 스토리·§2 증거·§6 점검에 반영하되,
해당 내용이 없는 항목은 **"시나리오 없음" + "15%+ 복귀 조건"** 형태로 간결히 기재한다.
15%+ 복리가 구조적으로 어려우면 §2 반대 증거 우세 → TL;DR이 "NO" 또는 "조건부"로 자연 도출된다.

### 0. 이 회사는 무엇을 하는가 — 첫독자 컨텍스트

verdict는 서버 업로드 산출물이라 **이 종목을 처음 보는 독자**도 TL;DR 판정을 이해해야 한다.
TL;DR 앞에 **"회사 정체성 + 성장 축별 해자 높이 + 판정의 구조적 이유"** 블록을 둔다.
전문용어는 첫 등장 시 **괄호 주석**으로 1회 풀어쓴다 (예: "RPO(향후 인식될 계약 백로그)").

```markdown
## 이 회사는 무엇을 하는가

{문단 1 — 사업 정체성 · 전통 수익원 · 카테고리 원형 (3~5줄)}
- 무엇을 파는 회사인가, 누가 주 고객인가
- 어떤 구조적 특성(어뉴이티·사이클·자산 집약 등)이 카테고리를 결정하는가
- 예: "40년 된 엔터프라이즈 DB·SaaS 기업. 매출의 77%가 반복 구독(어뉴이티) 성격 → Stalwart(안정 복리형) 원형."

{문단 2 — 주 성장 축·현재 스토리 중심 (4~6줄)}
- 최근 주가·스토리를 움직이는 핵심 축 1~2개
- 구체 수치 (규모·성장률·가이던스·주요 계약)
- 전문용어는 괄호 주석 1회
- 예: "2024년 이후 중심은 OCI (Oracle Cloud Infrastructure) — AWS·Azure와 경쟁 … RPO(향후 인식될 계약 백로그)가 1년 만에 4배 급증."

{문단 3 — 현재 핵심 질문·판정의 이중 구조 (3~5줄)}
- 이 종목 판정의 축소 불가능한 단일 질문
- 지지·반대가 공존하는 구조적 이유
- 예: "Stalwart 어뉴이티 + Fast Grower AI 인프라가 한 몸에 공존. 15%+ 판정의 핵심은 이 AI 캡엑스 사이클이 계획대로 수익화되는가다."

**핵심 성장 축의 해자 높이** (자세한 판정: [base §2](./{TICKER}_base.md)):

- **{성장 축명 A} (규모)**: **{해자 유형} · 강함 / 중간 / 약함 / 해자 없음** — {근거 한 줄, 수치 1개}
- **{성장 축명 B} (규모)**: **{해자 유형} · 강함 / 중간 / 약함 / 해자 없음** — {근거 한 줄, 수치 1개}
- **{성장 축명 C} (규모)**: **{해자 유형} · 강함 / 중간 / 약함 / 해자 없음** — {근거 한 줄, 수치 1개}

> "해자 없음" = base §2-2에서 "해자 성립" 받은 항목이 없음 (미검증·해자 아님만 존재). 해당 성장 축은 해자에 의해 보호되지 않으므로 §1-2 원인 체인·§2-1 지지 증거에서 해자를 근거로 삼을 수 없다.

> **핵심 관찰**: {성장 기대·해자 강도의 비대칭, 혹은 판정을 "조건부/NO"로 만드는 구조적 이유 한두 문장}.
```

**작성 규칙**:
- **20~30줄 범위**. 축약 실패 시 base 요약에 불과해진다 — 목적은 "판정의 배경"이지 "회사 전체 서술"이 아니다
- 전문용어(OCI·RPO·BYOL·IG 등급·Cerner 등) 첫 등장은 **괄호 또는 인용 블록 1회 주석**. 두 번째 등장부터는 약어만
- **해자 높이 리스트 판정 기준**:
  - **대상은 base §2-2에서 "해자 성립" 받은 해자만**. "미검증"·"해자 아님"은 해자가 아니므로 이 리스트에 등급을 매기지 않는다 (해당 성장 축에 성립된 해자가 없으면 "해자 없음"으로 표기하고 §1-2·§2-1에 해자 근거 금지)
  - **강함 / 중간 / 약함 3단계**는 성립된 해자의 **현재 강도**를 판정한다. base §2-2 증거 검증 수준(해자 성립은 전제)에 더해 **§2-3 지속성 지표 추세(ROIC·마진·시장점유율·재계약률 방향)** × **§2-5 훼손 징후 유무**의 종합 판정
  - 기계적 임계치 금지 — "ROIC 20% 이상이면 강함" 같은 고정 룰 대신 섹터 맥락과 추세 방향으로 판정자가 서술
  - 예: "강함 = 성립된 해자 + 지속성 지표 상승 또는 고정 + 훼손 징후 없음 / 중간 = 성립 + 지표 횡보 또는 소폭 둔화 / 약함 = 성립했으나 지표 뚜렷한 둔화 또는 훼손 징후 관찰"
- **핵심 관찰 블록쿼트**는 TL;DR 판정(YES/조건부/NO)의 **구조적 이유**를 한두 문장으로 직결시켜야 한다. 단순 요약이면 실패
- 수치는 base 링크로 갈음. §0에 숫자 복제는 최소화 (성장 축 규모·대표 수치 1~2개만)
- §0는 `## 판정 (TL;DR)` **바로 위**에 위치한다

**이 블록을 두는 이유**:
- philosophy "판정은 드러나지 않은 가치를 찾는 일" — 그 "가치"가 어떤 회사에서 나오는지 독자가 모르면 판정은 공허하다
- TL;DR만으로는 **해자-성장 비대칭** 같은 구조적 논점을 전달하기 어렵다. 해자 높이 리스트로 압축한다
- Cyclical·Slow Grower 등 15%+ 복리 적합성이 낮은 카테고리도 §0 유지 권장 (왜 구조적으로 어려운지를 첫독자에게 설명해야 하므로)

### 판정 (TL;DR)

**10줄 내 판정·근거가 끝나야 한다**. 여기서 판정이 안 서면 뒤 섹션은 못 쓴다.

```markdown
## 판정 (TL;DR)

**15%+ 복리 판정**: YES / 조건부 / NO

**판정 근거 3줄**:
1. {핵심 지지 근거 — 수치 포함}
2. {핵심 지지 근거 — 수치 포함}
3. {핵심 반대 근거 또는 조건 — 수치 포함}

**조건부인 경우 유지 조건**: {구체 수치·이벤트 — "경영진이 잘하면" 같은 모호 금지}

**주요 리스크 1줄**: {이 판정을 뒤집을 최대 요인}

**DCF 범위**: Bear ${X} / Base ${Y} / Bull ${Z} · 현재가 ${P}
```

**작성 규칙**:
- YES/조건부/NO 세 선택지만. "보류", "추후 판단" 금지 (판정 미완)
- "근거 3줄"은 **반대 증거 최소 1개** 의무 (지지 2 + 반대 1 권장 비율)
- "조건부" 판정 시 조건은 **구체 수치·이벤트** 형태여야 한다

### 1. 스토리 — "15%+ 가려면 무엇이 일어나야 하는가"

§1은 두 축이다. **§1-1은 "무엇이 일어나야 하는가"(내러티브)**,
**§1-2는 "왜 일어날 수밖에 없는가"(구조적 원인 체인)**.
스토리는 있는데 원인 체인이 없으면 희망 사항이고, 원인 체인은 있는데 스토리가 없으면 증거 나열.

#### 1-1. 스토리 한 문단

[01_philosophy.md](01_philosophy.md) "스토리 = 드러나지 않은 가치" 직접 구현.
**한 문단(5~8줄)**으로 기술. 장황하면 스토리가 아니라 서술.

```markdown
{5~8줄 한 문단 — 아래 요소를 서사로 엮는다}
- 주 성장 동력 1~2개 (구체 수치)
- 해자가 이 동력을 보호하는 메커니즘
- 목표 시간축 (10년 / 15년+)
- 성공 조건 (무엇이 유지/전환되어야 하는가)
- 이 스토리가 깨지는 단일 지점 1개
```

**작성 규칙**:
- "매출 성장"만 쓰면 실패. 어디서·어떻게·얼마만큼이 들어가야 한다
- 시간축 없는 스토리 금지. "장기적으로 성장"은 스토리가 아니다
- 깨지는 단일 지점은 §7 감지 대시보드에 구체 수치·이벤트로 등록 (감지만 수행, 판정은 §1-2에서)

#### 1-2. 15%+ 실현 구조 — 시나리오를 강제하는 원인 체인

스토리는 "무엇이 일어나는가"를 말하고, 이 표는 "왜 일어날 수밖에 없는가"를 말한다.
구조적 원인이 없으면 스토리는 희망 사항에 불과.
[01_philosophy.md](01_philosophy.md) §해자 "경쟁 배제는 복제 난이도에서 나온다" 직접 구현.

```markdown
| # | 구조적 원인 | 원인이 작동하는 메커니즘 | 실증 증거 (현 시점) | base 참조 | 붕괴 감지 조건 (수치·이벤트) | 현재 상태 |
|---|------------|----------------------|-------------------|---------|---------------------------|---------|
| 1 | {예: DB 이동 불가} | {예: 데이터 주권·레이턴시·재작성 비용} | {예: 갱신율 97%, RPO $300B} | [base §2-2] | {예: 갱신율 <90% · RPO QoQ 역성장 · 대형 고객 이탈 공시} | 유지 중 |
| 2 | ... | ... | ... | ... | ... | 유지 중 |
| 3 | ... | ... | ... | ... | ... | 유지 중 |
```

**작성 규칙**:
- **3~5개**. 1~2개면 스토리 취약, 6개 이상이면 원인 희석 (본질 원인은 소수)
- "구조적 원인"은 **회사 내부 구조·해자**에 뿌리박혀야 함. "AI 시장 성장" 같은 산업 트렌드만으로는 실격 — 왜 이 회사가 그 트렌드를 잡을 수밖에 없는가를 써야 함
- "메커니즘"은 원인이 성장을 **강제**하는 인과. "고객이 많음" (X) → "고객이 이탈 시 데이터 재구축 비용 $X, 그래서 못 나감" (O)
- "증거"는 **한 줄 요약만**. 상세 수치는 [base 링크] + §2-1 지지 증거로 연결 (중복 저장 금지)
- **"실증 증거" 열은 base §2-2에서 "해자 성립" 받은 근거 또는 §2-3/§1 단위경제학에서 실측된 수치만 사용**. "미검증" 해자 후보는 구조적 원인의 실증 증거로 쓸 수 없다 (원인 체인이 회사 주장에만 기대면 스토리 검증이 성립하지 않음)
- **현재 상태는 신규 분석 시 전부 "유지 중"으로 초기화**. 분기마다 **강화 중 / 유지 중 / 약화 중 / 붕괴** 중 하나로 갱신되며 추이는 trajectory에 누적
- 최소 1개는 **§2-1 지지 증거와 동일 base 참조**를 공유해야 함 (스토리와 증거가 끊기지 않도록)
- **붕괴 감지 조건 열**에는 해당 원인이 더 이상 작동하지 않는다고 볼 수 있는 **구체 수치·이벤트**를 기재. 이 조건은 감지 도구이지 자동 판정 규칙이 아니다 — 히트했다고 자동 "붕괴"가 아니라, 일회성 vs 구조적 맥락을 보고 판정자가 상태를 결정한다
- **§1-2 원인 체인 상태 판정이 스토리 검증의 유일한 판정 지점**. §7은 감지 대시보드이지 별도 판정 경로가 아니다
- **§1-2 각 행의 붕괴 감지 조건은 §7 감지 대시보드에 1:1로 반영**한다 (§7은 §1-2의 감지 수치를 한 곳에 모아보는 뷰)

### 2. 15%+ 판정 근거 — 지지/반대 대등

[01_philosophy.md](01_philosophy.md) "지지 증거와 반대 증거를 대등하게" 강제 구조.
한쪽 테이블이 비면 작성 미완.

#### 2-1. 지지 증거 (pro-15%+)

```markdown
| 렌즈 | 증거 | 핵심 수치 | base 참조 |
|-----|-----|--------|---------|
| 해자(현재) | {내용} | {수치} | [base §2-2] |
| 해자(영속성) | {내용} | {근거} | [base §2-6] |
| 성장 | {내용} | {수치} | [base §3-1] |
| PER 질 | {내용} | {수치} | [base §3-3, §4-1] |
```

**렌즈 열**은 philosophy 가치관 8축(장기투자·이익·성장·해자·PER·부채·경영진·분류)에서 선택.

**해자 렌즈 분할 규칙**:
- 해자 렌즈는 **"해자(현재)" · "해자(영속성)" 두 종류로 구분**해 사용한다 (같은 "해자"라도 판정 축이 다르므로 병기 금지)
- **해자(현재)** = base §2-2에서 "해자 성립" 받은 항목만 근거로 인용. §2-3 추세·§2-5 훼손 징후도 보조 근거 가능. **"미검증" 항목은 여기에 올 수 없다**
- **해자(영속성)** = base §2-6에서 "YES" 또는 "조건부(유지 조건 명시)" 받은 영속성 판정만 근거로 인용. §2-6 "NO"는 §2-2 반대 증거로만 기재
- 두 렌즈 모두 해당되는 해자가 있으면 **두 줄로 분리해 기재**. 하나의 해자를 한 줄에 섞어 쓰면 우열 판정(§2-3)에서 어떤 판정 축의 증거인지 구분 불가

#### 2-2. 반대 증거 (contra-15%+)

```markdown
| 렌즈 | 증거 | 핵심 수치 | base 참조 |
|-----|-----|--------|---------|
| 해자 검증 부재 | {미검증 해자 후보} | {검증 미확보 사유} | [base §2-2] |
| 해자 영속성 | {§2-6 NO 또는 조건부 취약 축} | {근거} | [base §2-6] |
| 규모 저항 | {내용} | {수치} | [base §3-1] |
| 부채 | {내용} | {수치} | [base §5-1] |
```

**작성 규칙**:
- 지지만 나열하면 확증 편향. **반대 증거 최소 3개** 의무
- base에 반대 증거가 부족하면 [02_base_guide.md](02_base_guide.md) §6(리스크) 재확인.
  그래도 없다면 "반대 증거 부재 — 추가 리서치 필요" 자체를 반대 증거로 기록
- **§2-2 "미검증" 항목이 있으면 "해자 검증 부재" 렌즈로 반드시 기재** — 회사 주장을 검증하지 못한 상태를 반대 증거로 명시해 판정자가 확증 편향에 빠지지 않도록 한다
- **§2-6 영속성 판정이 "NO" 또는 "조건부"면 "해자 영속성" 렌즈로 기재** — 조건부는 유지 조건이 깨질 가능성을, NO는 장기 해자 부재를 반대 증거로 표면화

#### 2-3. 우열 판정

```markdown
**우열 판정**: 지지 우세 / 반대 우세 / 팽팽함

**판단 이유** (3~5줄):
- {어느 쪽이 더 무거운지와 그 이유}
- {지지 증거가 반대 증거를 무력화할 수 있는가 / 없는가}
```

**작성 규칙**:
- 단순 개수 비교 금지. 증거의 **질·지속성·치명성**으로 판단한다
- "팽팽함"이면 TL;DR 판정은 **"조건부" 또는 "NO"** 권장 (불확실한 YES 경계)

### 3. 10배 요소 판정

[01_philosophy.md](01_philosophy.md) 성장 선언 1번 "10배 성장 요소를 찾는다" 직접 매핑.
**없으면 "없음"이라 쓴다**. 억지로 만들지 않는다.

```markdown
| 10배 동력 후보 | 현재 규모 | 10배 경로 | 15년+ 지속성 | 판정 | base 참조 |
|------------|--------|--------|-----------|-----|---------|
| {동력 1} | {규모} | {어떻게 10배} | {근거} | 있음/부분/없음 | [base §X] |

**종합 판정**: 10배 요소 {있음 / 부분 / 없음}
**근거 한 줄**: {핵심 동력 또는 없는 이유}
```

**작성 규칙**:
- "10배 경로"는 구체적이어야 한다. "시장 확장"이 아니라 "TAM $X → $10X, {메커니즘}"
- **"15년+ 지속성" 열은 base §2-6 영속성 판정 결과를 명시 인용** — YES/조건부/NO 표기 + base §2-6 링크. §2-6 "NO"인 경우 10배 동력이 있어도 15년 내 해자 훼손 가능성을 근거에 반영
- Stalwart 카테고리는 "부분 또는 없음"이 흔하다 — 솔직하게 쓴다
  (10배 없어도 15%+ YES 가능. 둘은 독립 판정)

### 4. 카테고리 결론

```markdown
**카테고리**: {base 측정 전 컨텍스트에서 복사}
**전환 방향**: {예: Stalwart 유지 / Fast Grower → Stalwart / Cyclical → Stalwart 일부 성격 부상}
**영속성 판정** (base §2-6): **YES / 조건부 / NO** — {유지 조건 또는 취약 축 한 줄}
**카테고리별 강조점이 이번 판정에 미친 영향**:
- {1~3줄 — 예: "Stalwart 침체기 실적에서 이익 20%+ 낙폭 확인 → TL;DR 조건부 판정 기여"}
- {예: "Cyclical이라 평생 보유 복리와 긴장 — §2-6 영속성 조건부 + §6-2 요구 CAGR 달성 경로 제한적"}
```

**작성 규칙**:
- 카테고리는 게이트가 아니라 **서술적 분류**. 판정(YES/조건부/NO)은 §2 증거에서 직접 도출한다
- 모호하면 두 카테고리 병기 + 전환 방향으로 해소
- Cyclical·Slow Grower·Turnaround·Asset Play 카테고리여도 §1~7 동일 프레임워크로 수행한다.
  15%+ 복리가 구조적으로 어려운 카테고리는 §2 반대 증거 우세로 TL;DR이 자연스럽게 "NO" 또는 "조건부"로 도출된다
- **영속성 판정 블록은 base §2-6 결과를 그대로 인용**한다 (verdict에서 재판정 금지 — §2-6이 단일 출처). 영속성 "NO" 또는 "조건부"면 **§2-2 반대 증거에 "해자 영속성" 렌즈로 반드시 반영**한다. TL;DR 판정은 §2 우열 판정에서 자연스럽게 도출되며 — 영속성이 반대 증거 무게 중심에 들어가면 "YES" 유지가 어려워질 것 — 여기서 게이트로 강제하지 않는다 (philosophy "판정은 §2 증거에서 직접 도출된다" 원칙 준수)

### 5. 회피 게이트 (부채 · 경영진)

[01_philosophy.md](01_philosophy.md) 회피 관점(부채·경영진)을 **게이트**로 구현.
**하나라도 "실패"면 TL;DR 판정을 "조건부" 또는 "NO"로 강등**한다.

```markdown
| 게이트 | 판정 | 핵심 근거 | base 참조 |
|-------|-----|---------|---------|
| 부채 취약성 | 통과 / 주의 / 실패 | 순현금/이자커버리지 수치 | [base §5-2] |
| 경영진 신뢰 | 통과 / 주의 / 실패 | 자본배분·M&A 트랙레코드 | [base §4-3] |
```

**판정 기준 (판정자 서술 — 고정 임계치 금지, 섹터·비즈니스 모델 맥락 우선)**:

- **부채 취약성**: base §5-1 부채 구성·§5-2 상환 능력 지표·§5-3 FCF 추세를 **섹터 표준 대비**로 판정. 금융사처럼 이자커버리지 개념이 의미 없는 업종은 업종 고유 지표(자본비율·NIM 안정성 등)로 대체
  - **통과**: 사이클 저점에서도 생존 + 복리 엔진 가동 유지 가능
  - **주의**: 생존은 가능하나 사이클 저점에서 자본배분·재투자가 제약될 가능성
  - **실패**: 사이클 저점에서 생존 리스크 또는 희석·유상증자·배당 삭감 가능성
- **경영진 신뢰**: base §4-1 자본배분 이력·§4-2 투입 결과·§4-3 발언 vs 결정 트랙레코드 종합 판정
  - **통과**: 자본배분 일관성 + M&A ROI 입증 + 장기 시야
  - **주의**: 일부 자본배분 실수 또는 단기 실적 방어 신호
  - **실패**: 반복적 M&A 과지불·자본배분 일관성 부재·주주가치 훼손 신호 반복

**실패 게이트 처리**: TL;DR 판정 재확인 — "YES" 금지, "조건부/NO"로 조정되어야 한다.

### 6. 가격 범위 · 15% 경로 기준선

§6는 두 축을 분리해 다룬다. **§6-1은 "주가가 어디 있나"(가격 위치)**, **§6-2는 "실적이 어디 가야 하나"(실적 궤도)**.
§6-1은 신규 분석 시 DCF 범위 표기, §6-2는 분기 궤도 점검의 정량 기준선.

#### 6-1. 가격 범위 (표기 only)

base §7-3 (3시나리오 DCF) 결과 복사. **새로운 DCF 계산 금지**.

```markdown
| 시나리오 | 목표가(중간) | 현재가 대비 수익률 | 핵심 전제 |
|---------|---------|-----------------|--------|
| Bear | ${X} | {%} | {전제 한 줄} |
| Base | ${Y} | {%} | {전제 한 줄} |
| Bull | ${Z} | {%} | {전제 한 줄} |

**현재가**: ${P} (기준일 YYYY-MM-DD)
**범위**: ${Bear} ~ ${Bull}

**시장 참고 수치** (분기 갱신 — 내 DCF 범위와 시장 기대의 격차 추적):
- 52주 범위: ${L} ~ ${H}
- 애널리스트 평균 목표가: ${A} ({n}명 기준)
- YTD 수익률: {%}
```

**작성 규칙**:
- **매수/매도 판정 금지**. "현재가가 Base 이하면 매수" 같은 문장 금지
- "현재가가 어느 구간에 있다"는 **관찰 기록**만 허용
- 가중평균 단일 목표가 금지 (philosophy·base 일관성)
- **시장 참고 수치 블록**은 분기마다 갱신 대상. 내 DCF 범위와 시장 기대(애널리스트 목표가)의 격차가 좁혀지는지·벌어지는지가 스토리 검증 시그널
- 애널리스트 목표가는 참고만, **가중치로 쓰지 않는다** (철학 위반)

#### 6-2. 15% 경로 기준선 (분기 궤도 점검 기준)

[01_philosophy.md](01_philosophy.md) §성장 "필요 연평균 성장률" 렌즈 구현.
분기 실적이 이 경로 위에 있는지가 "15%+ 판정 유지"의 정량 기준점.
**주가 선납 여부는 §6-1 DCF 범위가 이미 판정하므로 여기에는 포함하지 않는다** — §6-2는 순수하게 기업 실적 궤도만 본다.

```markdown
| 축 | 값 | 근거 |
|----|----|------|
| 시간축 | {t}년 | §1-1 스토리 시간축과 일치 |
| 배당수익률 | {Y}% | [base §X] |
| **요구 EPS CAGR** | **{N}%** | (1.15)^t / (1+Y)^t 역산 |
| 관측 TTM EPS 성장 | {M}% | [base §X] |
| 관측 매출 성장 | {L}% | [base §X] |

**궤도 판정 (판정자 서술)**:
- **✓ 유지 / ⚠ 일시 이탈 / ✗ 구조 이탈** 중 하나를 고르고 **판단 근거 한 줄**을 필수 기재한다
- 판단 근거는 **§1-2 구조 원인 체인 상태(강화 중 / 유지 중 / 약화 중 / 붕괴)와의 정합성**을 명시해야 한다
  - 예: "EPS 미달이지만 §1-2 원인 전부 '유지 중' + 매출 성장 유지 → 회계 일회성 ⚠ 일시 이탈"
  - 예: "EPS는 요구 CAGR 상회이지만 §1-2 원인 2개 '약화 중' → 전조 ⚠"
  - 예: "EPS·매출 동반 둔화 + §1-2 원인 '약화 중' 동반 → ✗ 구조 이탈"
- ✗ 구조 이탈 → TL;DR 판정 강등 후보
```

**작성 규칙**:
- 시간축은 **§1-1 스토리 시간축과 반드시 일치**시킨다 (§1-1에서 10년이라 했는데 §6-2에서 5년이면 내부 모순)
- 배당수익률이 0에 가까우면 표에 0으로 기재 후 계산 단순화 (요구 CAGR ≈ 15%)
- **EPS 단일 지표 금지** — TTM EPS는 일회성 회계·일시 요인에 민감하므로 매출 성장을 병기해 판정자가 노이즈를 걸러낸다
- **역산 허용 PER은 §6-2에 넣지 않는다** — DCF 범위(§6-1)가 이미 동일 축을 더 정교하게 다루므로 중복 + 가격 판정 경계 위반 우려
- **분기 업데이트 시 §1-1 스토리 시간축이 이동하면 §6-2 요구 CAGR도 함께 재산출**한다 (시간축·배당수익률은 고정값이 아니라 스토리와 동기화되는 파생값). 스토리 시간축 자체가 구조적으로 바뀌면(예: 10년 → 5년 축약) verdict 전면 재작성 계기
- **기계 규칙 금지** — "N분기 연속 미달" 같은 기계적 분류 대신 판정자가 매 분기 §1-2 구조 원인 체인 상태와 교차해 판정한다. 일회성·계절·사이클·구조 이탈의 구분은 판정자 서술로만 가능

### 7. 감지 대시보드 — 스토리·원인·게이트 훼손 감지 수치 집약

스토리 전제 깨짐·§1-2 원인 붕괴·§5 회피 게이트 훼손을 **한 곳에서 감지하는 수치·이벤트 대시보드**.
base §6-5 Inversion 조건과 연결된다.

**§7은 감지 섹션이지 판정 섹션이 아니다**. 판정은 §1-2 원인 체인 상태 + §5 회피 게이트에서 내려지며,
§7은 그 판정을 내릴 때 **입력값으로 참조하는 감지 도구 모음**이다. 여기 히트가 자동 재작성 트리거가 아니다 —
히트를 §1-2 원인 "약화 중 / 붕괴"로 해석할지는 맥락(일회성 vs 구조적)을 판정자가 서술한다.

```markdown
| # | 감지 조건 (수치·이벤트) | 대응 판정 대상 | base 참조 |
|---|---------------------|-------------|---------|
| 1 | {§1-1 스토리 전제 깨짐 — 구체 수치} | §1-1 스토리 | [base §6-5] |
| 2 | {§1-2 원인 #N 붕괴 감지 — §1-2 표의 동일 조건} | §1-2 원인 #N | [base §X] |
| 3 | {§5 게이트 훼손 — 부채 or 경영진} | §5 회피 게이트 | [base §5-1 or §4-3] |
```

**작성 규칙**:
- 최소 3개, 최대 7개. 1개면 감지망 부실, 10개 넘으면 주의력 분산
- 각 조건은 **구체 수치·이벤트** 형태 (모호한 "업황 악화" 금지)
- §1-1 스토리의 "깨지는 단일 지점"이 이 대시보드 중 하나에 포함되어야 한다
- §1-2 원인 체인의 **붕괴 감지 조건 열과 1:1 연결** — 원인 항목은 §1-2 해당 행의 감지 조건을 그대로 옮겨 적는다 (단일 출처 유지, §1-2 수정 시 §7도 동기화)
- **"대응 판정 대상" 열 필수** — 각 감지 항목이 어느 판정(§1-1/§1-2/§5)의 입력값인지 명시. 판정 장소를 분산시키지 않기 위한 장치
- **히트 = 자동 재작성 금지**. 히트 시 §1-2 원인 상태 판정을 재수행하고, 판정 결과가 "붕괴"면 재작성, "약화 중"이면 강등 후보, "유지 중(일회성)"이면 유지

## 체크리스트 — 작성 완료 전 확인

- [ ] §0 "이 회사는 무엇을 하는가" 블록에 **(a) 사업 정체성 (b) 주 성장 축 + 현재 스토리 (c) 현재 핵심 질문**의 3문단이 모두 있는가
- [ ] §0에 **핵심 성장 축의 해자 높이 리스트** (축명 + 해자 유형 + **강함/중간/약함/해자 없음** 등급)가 있는가. 등급 대상이 base §2-2 "해자 성립" 항목에 한정되었고, "미검증"을 해자로 올리지 않았는가
- [ ] §0 **핵심 관찰 블록쿼트**가 TL;DR 판정의 구조적 이유를 한두 문장으로 연결하는가
- [ ] §0 전문용어가 첫 등장 시 **괄호 주석 1회** 풀어쓰였는가 (RPO·OCI·IG 등급·Cerner 등)
- [ ] TL;DR 판정이 YES/조건부/NO 중 하나로 명시되었는가 (보류 금지)
- [ ] TL;DR 근거 3줄에 **반대 증거 최소 1개** 포함되었는가
- [ ] "조건부" 판정이라면 조건이 **구체 수치·이벤트** 형태인가
- [ ] §1-1 스토리에 **시간축과 성공 조건과 깨지는 단일 지점**이 명시되었는가
- [ ] §1-2 **구조 원인 체인이 3~5개** 기록되었고 각 행에 원인·메커니즘·증거·base 참조·**붕괴 감지 조건(수치·이벤트)**·"유지 중" 초기 상태가 모두 있는가
- [ ] §1-2 원인 체인 각 행의 **붕괴 감지 조건이 §7 감지 대시보드에 1:1로 동기화**되었는가 (§1-2가 단일 출처)
- [ ] §2-1 지지 증거의 해자 렌즈가 **"해자(현재)"와 "해자(영속성)"로 분리**되어 있고, "해자(현재)"는 base §2-2 "해자 성립" 항목만, "해자(영속성)"는 base §2-6 YES/조건부 결과만 인용했는가
- [ ] §2-2 반대 증거가 **최소 3개** 기록되었는가 (없으면 "부재 확인" 메모). base §2-2 "미검증" 항목이 있으면 "해자 검증 부재" 렌즈로, §2-6 NO/조건부면 "해자 영속성" 렌즈로 기재되었는가
- [ ] §2-3 우열 판정이 증거 **질·지속성·치명성** 기반인가 (개수 비교 금지)
- [ ] §3 10배 요소 판정이 "있음/부분/없음" 중 하나로 명시되었고, **"15년+ 지속성" 열에 base §2-6 판정(YES/조건부/NO)이 명시 인용**되었는가
- [ ] §4 카테고리 결론에 **전환 방향** · **base §2-6 영속성 판정 인용** · **카테고리별 강조점의 판정 기여**가 기재되었는가. 영속성 "NO/조건부"가 **§2-2 반대 증거에 "해자 영속성" 렌즈로 반영**되어 §2-3 우열 판정에서 무게 평가되었는가
- [ ] 15%+ 복리가 구조적으로 어려운 카테고리도 §5~7이 동일 구조로 기재되었고, 내용이 없는 항목은 "시나리오 없음 + 15%+ 복귀 조건" 형태로 남았는가
- [ ] §5 회피 게이트에 실패 항목이 있다면 TL;DR 판정이 "조건부/NO"로 조정되었는가
- [ ] §6-1 가격 범위에 **매수/매도 판정 문장이 없는가**
- [ ] §6-2 15% 경로 기준선에 **요구 EPS CAGR이 구체 % 값**으로 기재되었고 §1-1 시간축과 일치하며, **관측 TTM EPS + 매출 성장 + §1-2 원인 체인과의 정합성 서술**이 포함되었는가
- [ ] §7 **감지 대시보드**가 3~7개 범위에 있고 §1-1 깨지는 단일 지점 + §1-2 원인 붕괴 감지 조건 + §5 게이트 훼손 감지를 포함하는가. 각 행의 **"대응 판정 대상" 열**이 기재되어 판정 장소가 §1-1/§1-2/§5로 명확히 배정되었는가
- [ ] 모든 증거에 **base 참조 링크**가 있는가 (verdict에 수치 복제 없음)
- [ ] 전체 분량이 **150~270줄** 범위에 있는가 (§0 20~30줄 포함)
- [ ] 본문에 **체크리스트 적용 요약·작성자 확인 블록**이 없는가 (본문은 판정, 체크리스트는 외부 점검)

## 작성 순서 (권장)

판정이 편향 없이 나오려면 **증거부터 모으고 판정을 마지막에 쓴다**.

1. base.md 전부 읽기 — "15%+ 가능한가"의 잠정 답을 머릿속에 정한다
2. §2-1 지지 + §2-2 반대 증거 테이블 채우기 (편향 없이, 최소 각 3개)
3. §2-3 우열 판정
4. §5 회피 게이트 판정 (실패 시 §2 판정 조정)
5. §3 10배 요소 · §4 카테고리 · §6 가격 범위 채우기
6. §1-1 스토리 작성 (§2~5 판정의 내러티브 요약)
7. §1-2 구조 원인 체인 작성 — 스토리를 강제하는 3~5개 원인을 §2 증거에서 역으로 추출
8. §7 감지 대시보드 작성 — §1-2 원인 체인의 붕괴 감지 조건 + §1-1 깨지는 단일 지점 + §5 게이트 훼손 감지를 한 곳에 집약 (판정 섹션이 아닌 관찰 도구)
9. **TL;DR 작성** (위 전체의 10줄 압축)
10. **§0 "이 회사는 무엇을 하는가" 작성** — 마지막에 작성한다. §1~7·TL;DR 판정이 완성된 뒤여야 "핵심 관찰 블록쿼트"가 판정 구조를 정확히 반영할 수 있다
11. 체크리스트 확인

## 분기 업데이트 워크플로우 (실적 발표 후 재작성)

verdict는 **분기 실적 발표마다 재작성되는 살아있는 문서**다. 판정이 시간에 따라 어떻게 이동하는지 추적하려면 본문 덮어쓰기 + 스냅샷 보존 + 누적 내러티브의 3단 구조가 필요하다.

### 파일 역할 분담

```
02_tickers/{TICKER}/
├── {TICKER}_verdict.md          # 현재(최신) 판정 — 서버 업로드 기본
├── {TICKER}_base.md             # 현재(최신) 측정 원재료 (내부에 분기별 점검 기록 유지)
├── {TICKER}_trajectory.md       # 분기별 누적 맥락 (최신 블록이 위)
└── snapshots/
    └── {YYYY}Q{N}_verdict.md    # 분기별 verdict 스냅샷 (복원용)
```

- **verdict.md**: 항상 **현재 시점의 최선 판정**. 이력 테이블·요약 블록 포함 금지 (판정 밀도 희석)
- **base.md**: 항상 최신 측정. 내부 "분기별 점검 기록" 섹션에 수치 변화 로그 누적 (기존 방식 유지)
- **trajectory.md**: 분기별 블록의 누적. "이 회사가 어디로 가고 있는가"의 서사적 타임라인
- **snapshots/**: 과거 분기 verdict 원본 보존. "그때 내 판단은 이랬다"를 온전히 복원

### 업데이트 절차

1. **스냅샷 보존**: 이전 verdict.md를 `snapshots/{YYYY}Q{N}_verdict.md`로 복사 (직전 분기 식별자 사용)
2. **base.md 갱신**: 새 실적 수치 반영 + "분기별 점검 기록" 섹션에 이번 분기 행 추가
3. **verdict.md 재작성**: 본문 전체를 새 수치·새 스토리 검증 결과로 갱신 (§0~§7)
4. **trajectory.md 갱신**: **상단에** 이번 분기 블록 추가 (최신이 위). 이전 블록 편집·삭제 금지
5. 분기 업데이트 체크리스트 확인 (아래)

### 분기 업데이트 체크리스트 (단일 출처)

> 이 체크리스트는 본 가이드에만 존재한다. trajectory.md에 복제하지 않는다 (drift 방지·DRY).
> 분기 업데이트 요청 시 반드시 이 섹션을 먼저 열람하고 아래 항목을 순서대로 수행한다.

- [ ] base.md에 이번 분기 실적 수치 반영 (§1 매출 믹스, §3 세그먼트, §5 재무구조 등 해당 섹션)
- [ ] base.md "분기별 점검 기록" 섹션에 이번 분기 행 추가 (날짜·실적 요약·시나리오 위치 변화·팩트 업데이트)
- [ ] 이전 verdict.md를 `snapshots/{YYYY}Q{N}_verdict.md` 로 복사 (직전 분기 식별자)
- [ ] verdict TL;DR **조건부 유지 조건**을 1:1로 점검 (각 조건 ✓ 유지 / ✗ 위반 / 미검증 판정)
- [ ] verdict §7 **감지 대시보드** 점검 — 각 항목 히트·부분 경고·미히트 여부를 **관찰 기록만** 수행. 여기서 판정(붕괴/재작성 등) 내리지 않음. 이 관찰은 다음 단계 §1-2 원인 상태 판정의 **입력값**
- [ ] verdict **§6-2 15% 궤도 점검**: 이번 분기 TTM EPS + 매출 성장률을 요구 CAGR과 대조
  - ✓ 유지 / ⚠ 일시 이탈 / ✗ 구조 이탈 중 하나를 고르고 **§1-2 구조 원인 체인 상태와의 정합성**을 판단 근거 한 줄로 서술
  - **✗ 구조 이탈이면 "판정 이동 4분류"에서 강등 후보로 자동 승격**
  - **§1-1 스토리 시간축이 이번 분기에 이동했다면 §6-2 요구 CAGR도 재산출**
- [ ] verdict **§1-2 구조 원인 체인** 1:1 점검 — **분기 판정의 유일한 판정 지점**: 각 원인을 **강화 중 / 유지 중 / 약화 중 / 붕괴** 중 하나로 판정
  - §7 감지 대시보드의 히트·부분 경고를 **입력값**으로 사용. 히트 여부만으로 자동 "붕괴" 판정하지 않고, **일회성 vs 구조적** 맥락을 판정자가 서술
  - 이번 분기 실적·공시에서 해당 원인을 **강화하는 새 증거 / 약화시키는 새 증거**를 식별
  - **원인 체인 전체 무게중심을 판정자가 서술**(강화·유지 vs 약화·붕괴). 개수 카운트 금지 — 스토리를 지탱하는 **핵심 원인 1개가 약화**되면 주변 원인 다수가 유지 중이어도 강등 후보, 반대로 주변 원인 다수 약화라도 핵심이 강화면 유지 가능
  - **1개라도 "붕괴"(원인이 더 이상 작동 안 함) 판정 → verdict 전면 재작성**. 재작성 트리거는 §7 히트가 아니라 여기서 내려지는 "붕괴" 판정이다
- [ ] verdict §1-1 **스토리**에서 이번 분기 실적으로 입증·반증된 부분 식별
- [ ] **판정 이동 4분류** 중 하나 결정: 유지 / 강등(YES→조건부, 조건부→NO) / 승격(역방향) / 재작성(§1-2 원인 "붕괴" 판정 발생)
- [ ] 판정 이동이 "재작성"이면 verdict 본문 전면 재작성 수행 (§0~§7 전체)
- [ ] verdict §6-1 **시장 참고 수치** 블록 갱신 (52주 범위·애널리스트 목표가·YTD)
- [ ] trajectory.md 상단에 새 블록 추가 (포맷 준수: 판정 이동·숫자 하이라이트·**15% 궤도 상태**·**구조 원인 상태 변화**·스토리 검증·조건 상태·§7 감지 대시보드 상태·관찰 포인트·스냅샷 링크)
- [ ] trajectory 과거 블록 **편집·삭제 없음** 재확인 (오타 수정 외 불가침)
- [ ] trajectory 상단 포인터가 본 가이드로 연결되어 있는지 재확인 (단일 출처 유지)

### trajectory 작성 규칙

- **판정 이동 4분류**: 유지(같은 등급) / 강등(YES→조건부, 조건부→NO) / 승격(역방향) / **재작성**(§1-2 원인 "붕괴" 판정 → 스토리 전면 수정)
- **숫자 변화**는 base "분기별 점검 기록" 섹션의 하이라이트만. 전체 복제 금지 (base가 단일 출처)
- **15% 궤도 상태**는 verdict §6-2 요구 CAGR과 **정확히 같은 값**을 사용. 관측 TTM EPS는 base 분기 점검 기록에서 도출. 경로 평가(✓/⚠/✗)는 분기 업데이트 체크리스트 규칙에 따라 판정
- **구조 원인 상태 변화**는 verdict §1-2 원인 체인과 **원인명·번호가 1:1 대응**. 원인이 바뀌면(추가·제거·재정의) verdict 본문 전면 재작성 계기. trajectory에서만 원인을 바꾸지 않는다
- 원인 "붕괴" 판정 시 반드시 **해당 분기 블록에서 판정 이동 "재작성"**으로 표기하고 verdict 본문 전면 재작성 수행
- **조건부 유지 조건 상태**는 verdict §TL;DR의 조건과 **정확히 1:1 대응**해야 한다. 조건이 바뀌면 trajectory에서도 매핑 조정
- **§7 감지 대시보드 상태**는 verdict §7과 1:1 대응. 히트 자체는 재작성 신호가 아니며, §1-2 원인 상태 판정에서 "붕괴"가 나와야 재작성. 히트가 "약화 중" 판정으로 귀결되면 강등 후보(재작성 아님), "유지 중(일회성)"으로 귀결되면 판정 유지
- **블록 분량**: 한 분기 15~25줄 권장. 길어지면 내러티브가 아니라 재측정이 됨 — 그건 base 소관
- **과거 블록 불가침 원칙**: 오타 수정 외 과거 블록 편집 금지. 판단 이력이 사후 수정되면 학습 의미가 사라짐

### 다음 분기 업데이트가 아닌 신규 분석일 때

- 신규 티커 분석(처음 base + verdict 작성)은 본 가이드의 "작성 순서 (권장)"를 그대로 따른다
- **첫 분석 시점에도 trajectory.md는 생성**한다 — 1번째 분기 블록만 포함한 최소 상태
- snapshots/ 폴더는 첫 업데이트 시점(2번째 분기)에 생성된다 — 첫 분석 단계에선 빈 폴더 불필요
